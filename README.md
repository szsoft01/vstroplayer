# VSTRO 更新配置

本仓库保存 Vstro Player（`com.vs.vsplayer`）的更新提示配置。仅对已集成此功能的 VSTRO 客户端生效，应用安装与升级由 Google Play 完成。

## 配置入口

| 文件 | 使用场景 | Raw 地址 |
| --- | --- | --- |
| `update.json` | Release 正式包 | https://raw.githubusercontent.com/szsoft01/vstroplayer/main/update.json |
| `update-debug.json` | Debug 调试包 | https://raw.githubusercontent.com/szsoft01/vstroplayer/main/update-debug.json |

客户端读取 `main` 分支；修改其他分支或创建 GitHub Release 不会更新这些配置。Raw 不可用时尝试 GitHub Contents API 的同名文件。仓库必须保持可公开读取，文件中不要放密钥或用户信息。

## 配置格式

以下为示例，版本号必须对应已在 Google Play 对目标设备可用的实际版本：

```json
{
  "latest_version_code": 223,
  "latest_version_name": "8.8.1",
  "force_update": false,
  "update_title": "发现新版本",
  "update_message": "1. 优化播放体验\n2. 修复已知问题\n\n提升使用稳定性。"
}
```

| 字段 | 类型与限制 | 说明 |
| --- | --- | --- |
| `latest_version_code` | 整数，0–2100000000 | 与 Android `versionCode` 比较；0 关闭本功能提示；小于或等于本机版本时不提示 |
| `latest_version_name` | 字符串，最多 40 字符 | 展示版本名称；空值时显示版本号，不参与升级判断 |
| `force_update` | 布尔值 `true` / `false` | 有新版本时决定强制或可选；没有最低版本字段 |
| `update_title` | 字符串，最多 100 字符 | 更新页标题；空值使用默认标题 |
| `update_message` | 字符串，最多 2000 字符 | 仅填写版本更新内容，支持换行与空行；空值时仍显示客户端固定的商店指引 |

启用更新时，`latest_version_code` 和 `force_update` 必须提供正确类型。建议始终保留五个字段；JSON 不支持注释、尾随逗号或字符串中的未转义换行。文件最多 16 KiB（UTF-8）。

### 多行更新说明

在 JSON 字符串里写 `\n`（一个反斜杠加字母 n）；客户端解析后按实际换行显示。`\n\n` 显示一个空行。上例在简体中文客户端显示为（首段由客户端固定提供，后续为远端更新说明）：

```text
请通过 Google Play 完成更新。

1. 优化播放体验
2. 修复已知问题

提升使用稳定性。
```

不要写 `\\n`，它会变成可见的字面量 `\n`。不要使用 `<br>`，更新页使用纯文本显示。说明应简洁，并在电视上确认全部可见；2000 字符是输入限制，不代表一屏能显示全部内容。

商店跳转目标与“请通过 Google Play 完成更新”指引均固定在客户端，随客户端语言显示；配置不提供下载地址或商店地址，也不应在 `update_message` 中重复下发商店操作指引。

## 客户端行为

- 用户同意协议并离开启动页后，后台异步检查；检测失败不阻断启动，不改动账号、授权或播放流程。
- 获取到新版本后显示菜单、设置、About / 新版本红点，覆盖 Android 和 Linux 两种风格。
- About → 应用更新始终尝试打开本应用的 Google Play 页面，不受红点、配置关闭、检测失败或版本是否最新影响。无可用 Play 时尝试浏览器打开本应用的 Play 网页；两者均不可用时显示提示。
- 自动提示延迟约 15 秒；等待前台窗口获得焦点及原有访问状态允许。可选提示仅在账号、设置等指定页面出现；强制提示适用于可提示的前台页面。
- 可选更新显示“立即更新 / 稍后”。选择稍后（包括返回键）后，同一目标版本不再自动弹出，红点仍保留。
- 强制更新显示“立即更新 / 退出应用”。退出按钮及返回键关闭应用任务；历史“稍后”记录不能跳过强制更新。
- “立即更新”优先打开本应用的 Google Play 页面。无可用 Play 时尝试浏览器；两者均不可用时显示提示并保留更新页。强制模式仍可退出应用。
- 从商店返回但尚未更新时，更新页仍保留。安装到目标版本或更高版本后，不再显示该版本的更新提示。
- 不从 GitHub 下载 APK，不申请安装 APK 权限。配置可强制提示，但无法保证商店上架范围、账号、地区或设备兼容性；运营发布前必须实机确认。

## 网络与生效时间

更新请求使用独立 OkHttp 客户端直连，忽略系统 HTTP 代理；仅影响本更新请求，不修改系统代理或其他业务网络配置。系统 DNS 失败时尝试 Google / Cloudflare 的 DNS-over-HTTPS，保持 HTTPS 证书校验。

单轮请求总预算约 25 秒，Raw 优先、Contents API 后备；有短重试和超时、HTTP 限流处理。不同回退路径共用预算，不保证每轮都尝试完所有线路。DoH 不能保证突破运营商封锁、VPN 路由或网络断开。

成功检查后约 1 小时再次检查；失败后按 5 / 15 / 60 分钟退避，必要时遵守服务器退避时间。只在符合条件的前台页面调度。配置保存在进程内；重新启动进程会重新检查。GitHub/CDN 也可能缓存，提交后不保证所有设备立即生效。

## 发布、回退与验收

1. 先在 Google Play 发布版本，并确认目标账号、地区及电视设备确实可更新；灰度尚未覆盖全部目标用户时，不宜开启全量强制提示。
2. 优先修改 `update-debug.json`，用本地临时降低 `versionCode` 的测试包验收，无需为测试再发布新版本。验证可选、强制、红点、多行说明、商店回退和断网恢复。
3. 将确认后的配置提交到 `main/update.json`；用实际 Raw 地址检查返回内容，再用 Release 包进行真机验收。Debug 包默认读取调试文件，不能代替 Release 正式链路。
4. 撤销强制可将 `force_update` 改为 `false`；关闭更新提示可将 `latest_version_code` 改为 `0`，或恢复已确认的历史配置。
5. 回退在客户端下一次成功检查后生效。已经打开的强制更新页不会主动刷新配置；退出并重新启动应用可触发重新检查，仍需考虑 CDN 缓存。
6. 临时测试结束，恢复配置、源码版本号、设备原包与系统设置；保留应用数据。

关闭配置示例：

```json
{
  "latest_version_code": 0,
  "latest_version_name": "",
  "force_update": false,
  "update_title": "",
  "update_message": ""
}
```
